1. THE "gc" WHITE-LABEL FOOTBALL PLATFORM
--------------------------------------------------------------------------

DERIVED FROM THE CENSUS (deterministic, recomputed from
calendar-sources.json — not taken from any agent's report):

  calendar sources whose URL matches the `/matches` pattern ....... 64
  of those, fingerprinted EMBEDDED_NUXT_STATE ..................... 47
  distinct VENUES behind those 47 sources ......................... 47
  distinct DOMAINS behind those 47 sources ........................ 46
  acquisition_readiness of all 47 ................ TIER2_REUSABLE_FAMILY

CORRECTION TO THE CENSUS-01 REPORT: the estate is 47 venues, not 44. The
earlier figure understated it.

IMPORTANT CAVEAT — the URL pattern alone is NOT sufficient. Of the 64
sources matching `/matches`, 17 are NOT on this platform:
  EMBEDDED_NEXT_DATA 7, CLIENT_RENDERED_UNKNOWN 4,
  OTHER_EMBEDDED_APP_STATE 3, MICRODATA 2, ACCESS_BLOCKED 1.
Any collector must key off the platform's own markers, not the path.

LIVE VERIFICATION (bounded sample of 4, fetched 2026-09-20):

  HTTP  domain                        nuxt  VUE_APP_CLUB_ID      opta  gc
  200   accringtonstanley.co.uk       yes   accringtonstanleyfc  yes   yes

All four served a Nuxt hydration payload, a per-club `VUE_APP_CLUB_ID`
slug, and references to both Opta and the gc platform. The estate is
genuinely consistent: one implementation keyed on the shared platform
markers plausibly covers all 47.

NOT VERIFIED, and therefore NOT claimed: the public Opta JSON endpoint
shape reported by the earlier pass
(`matches.football.web.gc.<club>services.<tld>/v2/opta?...`) was NOT
exercised in this package. Only the 4 HTML pages above were fetched. That
endpoint remains an unverified lead, not an established fact.

NO COLLECTOR WAS BUILT. Phase 20 of this package forbids it.

--------------------------------------------------------------------------
2. WHY THIS MATTERS FOR TIER-2 COUNTS
--------------------------------------------------------------------------

These 47 sources sit inside TIER2_REUSABLE_FAMILY, which the Census-01
report correctly flagged as an UPPER BOUND rather than a count. Phase 15
of this package re-checks every TIER2-contributing source against its
family's own structural claim and conservatively downgrades the ones the
live page does not support — see `source-family-audit.json`.

The EMBEDDED_NUXT_STATE family is verified by the presence of a
`window.__NUXT__` / `__NUXT_DATA__` payload, which all four sampled
members demonstrably have, so this particular estate is expected to
survive that audit. The audit result, not this expectation, is the
authority.
