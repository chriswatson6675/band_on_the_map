## What this package adds

Band on the Map's architecture (`docs/ARCHITECTURE.md`,
`docs/OBSERVATION_PIPELINE.md`, `docs/VENUE_RESOLUTION.md`) is unchanged.
This package:

- adds a governed Porto source registry, `sources/porto.json` (19 entries,
  same schema/validator as `sources/lisbon.json`);
- implements two new, directly-proven Porto collectors — **Casa da
  Música** and **Teatro Municipal do Porto** (Rivoli/Campo Alegre) —
  reusing the existing bounded-HTML-listing collector family (the same
  shape already proven for MEO Arena/Capitólio), not a new architecture;
- adds `venues/porto.json` (2 evidence-backed venues, both `ADDRESS_ONLY`);
- extends `ingestion/venue/resolver.mjs` with Porto dispatch (still one
  shared, city-agnostic, exact-match resolver — no fuzzy matching added);
- adds one new manual entry point, `npm run ingest:lisbon-porto`, which
  runs the unchanged seven Lisbon collectors from
  `LISBON-AUTOMATIC-SUBSET-01` alongside the two new Porto collectors.

Nothing about the existing Lisbon pipeline, its fixtures, its 24/19/11/6
invariants, or `fixtures/map/lisbon-map-proof.json` was touched.

## Collector-family reuse analysis

Both new Porto sources reuse the exact same **bounded server-rendered
HTML listing** collector family already proven for MEO Arena (and, in
spirit, Capitólio): a single regex-based discovery module plus a small
observation-adapter, no new parsing infrastructure, no headless browser,
no universal scraper. `ingestion/http/fetch.mjs`, `ingestion/observation/
contract.mjs`, `ingestion/venue/resolver.mjs`, and `ingestion/map/
group-associated-listings.mjs` are all reused completely unchanged.

**No new collector family was required for either implemented Porto
source.**

Of the 9 sources in tonight's live run: 7 are JSON/RSS/ICS-structured
(78%), 2 are bounded-HTML (22%) — and even the bounded-HTML sources reuse
an already-established collector *shape*, not a new one.

Across the full two-city implemented set (9 sources): **100% reused an
already-established collector family** (JSON/API, RSS, ICS, or bounded
server-rendered HTML) — zero genuinely new collector families were added
by this package.

  subtitle (e.g. "Fado e Música Tradicional Portuguesa") retained

  `?categoria=musica` query parameter — every retained record is already
  source-classified as music by the site itself, not inferred by this
  project.
- Both existing Lisbon precedents (AgendaLX's explicit category filter,
  the multi-venue sources treated as "all events, honestly labelled") are
  followed rather than reinvented.

resolution failure, but a genuinely missing coordinate-evidence step,
exactly the same honest gap already on record for Lisbon's Village
Underground/BOTA venues in `docs/VENUE_RESOLUTION.md`.

## Known major source coverage gaps

- **Porto's biggest venues by reputation are the hardest to automate
  tonight**: Coliseu do Porto (React SPA), Maus Hábitos/Serralves/Vila do
  Conde's own agenda micro-site (all the same client-rendered JS
  builder platform) all require a headless-browser collector family this
  project does not have.
- **Hard Club** is a near-miss: a real, working first-party AJAX
  endpoint was found and fetched live, but its listing fragment exposes
  only a day-of-month, no month name — implementing it honestly would
  have required either fabricating a month or building extra scraping
  (a per-event detail fetch) not yet proven within this bounded session.
- **Porto's own official open-data "Agenda Cultural"** (CC-Zero licensed,
  structured, even carries lat/long) is the best rights/structure story
  found anywhere in this research — but is confirmed dead (last real data
  2019-2023). If the municipality ever resumes publishing to it, it
  would immediately outrank most other Porto sources.
- **7 of the 9 target Greater Porto municipalities** (all but Porto
  itself) have zero implemented sources tonight — every one has at least
  one *researched* lead (see table above), but none was technically
  proven within this session's bounded time.
- **Rivoli/Campo Alegre and Casa da Música coordinates** are the clearest
  near-term win — see "coordinate problems" above.
